TCP only carries a stream of bytes. RESP adds message boundaries on top: a one-byte type tag, then a length prefix. The server reads exactly that many bytes, so values can safely contain any bytes.

One thread, many clients. The server uses asyncio on top of kqueue/epoll instead of one thread per client. A coroutine waiting on a socket costs almost nothing, and the event loop wakes only the sockets that are ready.

All sockets are opened before any of them sends a command, so the server is holding them all at once. The thread count comes from ps on the real server PID. The few extra threads are asyncio's pool for fsync, so disk flushes never block the event loop. No client gets its own thread.

Consistent hashing, done by the client. Every client builds the same ring and picks the same node for a key, with no coordinator. If one node is kill -9ed, only its keys fail, and they fail fast. On restart it replays its write-ahead log.

Survivors dip a little after a kill because the same client threads also hit the dead shard's keys. That cost is on the client side; the surviving servers themselves are unaffected.

The cache defends itself at the protocol level. AUTH and TLS keep strangers out. For clients that do get in, the guard watches each connection's traffic, one-second window by one-second window, and decides whether it looks like an attack. It uses hand-written rules or a trained ML model, and it rate-limits or disconnects whatever it flags.
